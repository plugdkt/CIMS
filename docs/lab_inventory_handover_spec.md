# ข้อกำหนดการพัฒนา: ระบบแสดงผลและจัดการสต็อกคงคลังย่อย (Lab Inventory Handover Spec)

เอกสารส่งต่อสำหรับทีมพัฒนา (Developer Handover) เพื่อต่อยอดระบบบริหารจัดการคลังสารเคมีและวัสดุ (CMIS)

---

## 1. ปัญหาและที่มา (Problem Statement)

* **สถานการณ์ปัจจุบัน:** 
  * ระบบมีฟังก์ชัน "เติมสต็อก / รับเข้าคลังย่อย" (`/stock-in`) ใช้งานได้จริง และบันทึกข้อมูลลงตาราง `containers` และ `stock_ledger` ได้อย่างถูกต้องสมบูรณ์
* **ปัญหาที่พบจากผู้ใช้งาน:**
  * ผู้ใช้งาน (Lab Manager / Scientist / Staff) **ไม่สามารถมองเห็นข้อมูลสต็อกในคลังของตนเองได้เลย** เนื่องจาก:
    1. เมนูแถบข้าง **"รับเข้าคลังย่อย"** ลิงก์ตรงเข้าสู่แบบฟอร์มกรอกรับเข้า (`StockInController@create`) เสมอ ยังไม่มีหน้า Index สำหรับแสดงรายการคงคลัง
    2. เมนู **"ทะเบียนสารเคมี" (`/items`)** เป็นเพียง Master Catalog กลาง (706 รายการ) ไม่มีคอลัมน์แสดงยอดคงเหลือจริงในห้องปฏิบัติการของผู้ใช้
    3. หน้า **"รายละเอียดสารเคมี" (`/items/{id}`)** แสดงเฉพาะคุณลักษณะและเอกสารความปลอดภัย ยังไม่มีส่วนแสดงรายการภาชนะ/ขวดสาร (Containers) และสถานที่จัดเก็บจริงในห้องแล็บ

---

## 2. สถานะฐานข้อมูลและโครงสร้างปัจจุบัน (Current Backend Architecture)

* **User & Lab Scope:**
  * ผู้ใช้แต่ละคนผูกกับ `users.lab_id` (เช่น ผู้ดูแลแล็บผูกกับ Lab ID 1 "สำนักงานธุรการ")
* **Location Scope:**
  * สถานที่จัดเก็บผูกกับ `locations.lab_id`
* **Container & Ledger Data:**
  * ตาราง `containers`: มี `location_id`, `item_id`, `barcode`, `remaining_qty_base`, `status` (`SEALED`/`IN_USE`/`EMPTY`/`DISPOSED`), `lot_no`, `expiry_date`
  * ตาราง `stock_ledger`: บันทึกการรับเข้า (`RECEIVE`) และยอดคงเหลือแบบ Append-only

---

## 3. ขอบเขตงานที่ต้องพัฒนา (Scope of Work)

### งานที่ 1: พัฒนาหน้า "สต็อกคงคลังย่อยของฉัน" (My Lab Inventory)

* **เป้าหมาย:** สร้างหน้ารวมรายการสารเคมีและภาชนะทั้งหมดที่มีอยู่ในห้องปฏิบัติการของผู้ใช้
* **URL / Route:**
  * `GET /stock-in` หรือ `GET /inventory` เป็นหน้า Index แสดงรายการสต็อก (เช่น `StockInController@index` หรือ Livewire Component `App\Livewire\Inventory\LabInventoryTable`)
  * ย้ายแบบฟอร์มรับเข้าไปที่ `GET /stock-in/create`
* **เงื่อนไขการดึงข้อมูล (Query Scope):**
  * ดึง `Container` ที่ `status` อยู่ในสถานะ `SEALED` หรือ `IN_USE` (และ `remaining_qty_base > 0`)
  * กรองตาม `location.lab_id == auth()->user()->lab_id` (กรณี `ADMIN` สามารถมี Dropdown เลือกดูตามห้องแล็บได้)
* **ข้อมูลที่ต้องแสดงในตาราง:**
  1. บาร์โค้ดภาชนะ (`barcode`)
  2. รหัสสาร และชื่อสารเคมี (ไทย/อังกฤษ)
  3. เกรด (Grade) และสถานะทางกายภาพ (Physical State)
  4. สถานที่จัดเก็บ (`location.name` เช่น ห้องเก็บวัสดุ / ตู้สารเคมี)
  5. ปริมาณคงเหลือ (`remaining_qty_base` แปลงเป็น Display Unit) พร้อมหน่วยนับ
  6. วันหมดอายุ (`expiry_date`) พร้อมสีแจ้งเตือนหากใกล้หมดอายุ
  7. สถานะภาชนะ (Badge: ยังไม่เปิดใช้ `SEALED` / เปิดใช้งานแล้ว `IN_USE`)
* **เครื่องมือเสริมบนหน้าจอ:**
  * ช่องค้นหา (ค้นหาด้วยชื่อสาร, รหัสสาร หรือยิงบาร์โค้ด)
  * ตัวกรองตามสถานที่จัดเก็บ (Location Filter)
  * ปุ่มด้านบน: **"+ รับเข้าคลังย่อย (เติมสต็อก)"**
  * ปุ่มการกระทำท้ายแถว: **"พิมพ์สติกเกอร์บาร์โค้ด"** (ขนาด 40×25 มม. และ 50×30 มม. ผ่าน `ContainerLabelPdfService`)

---

### งานที่ 2: เพิ่มส่วนแสดงรายการภาชนะใน "หน้ารายละเอียดสารเคมี" (`/items/{id}`)

* **เป้าหมาย:** เมื่อเปิดดูข้อมูลสารตัวใด ให้เห็นทันทีว่าในห้องแล็บมีสารนี้อยู่กี่ขวด/ถัง และอยู่ที่ไหนบ้าง
* **ไฟล์ที่เกี่ยวข้อง:** `app/Http/Controllers/ItemController.php` และ `resources/views/items/show.blade.php`
* **รายละเอียดที่ต้องเพิ่ม:**
  * เพิ่ม Card หรือแท็บ **"รายการคงคลังในห้องปฏิบัติการ (Inventory in Lab)"**
  * ดึง `containers` ของ `$item->id` ที่อยู่ในห้องแล็บของผู้ใช้ (`whereHas('location', fn($q) => $q->where('lab_id', $user->lab_id))`)
  * แสดงตาราง: เลขบาร์โค้ด, จุดจัดเก็บ, วันที่รับเข้า, วันหมดอายุ, ปริมาณคงเหลือ, สถานะ, และปุ่มสั่งพิมพ์ฉลากบาร์โค้ดรายขวด

---

### งานที่ 3: ปรับปรุงเมนูแถบข้าง (Sidebar Navigation)

* **ไฟล์ที่เกี่ยวข้อง:** `resources/views/components/layout.blade.php` และ `lang/th/nav.php`
* **การปรับปรุง:**
  * ภายใต้กลุ่ม **"คลังสินค้า" (`nav.group_inventory`)**:
    * เพิ่มเมนู **"คลังสารเคมีของฉัน" (สต็อกคงคลัง)** ชี้ไปยังหน้ารายการสต็อก (`route('stock-in.index')`)
    * ปรับให้แสดงชัดเจนว่าเป็นหน้ารวมสต็อกพร้อมใช้งาน

---

## 4. ข้อกำหนดทางเทคนิคตามมาตรฐานระบบ CMIS (Non-Negotiable Rules)

1. **การคำนวณปริมาณ:** ใช้ `BCMath` (`scale = 6`) และฟังก์ชัน `UnitConverter` เสมอ ห้ามใช้ Float ของ PHP
2. **ความปลอดภัยและการตรวจสอบสิทธิ์:**
   * ควบคุมการเข้าถึงผ่าน Laravel Policy (เช่น `can('viewAny', Container::class)`)
   * ป้องกัน IDOR: ผู้ใช้ต้องเห็นเฉพาะสต็อกใน `lab_id` ของตนเองเท่านั้น ยกเว้นผู้มีสิทธิ์ระดับ `ADMIN` หรือ `AUDITOR`
3. **การแสดงผลข้อความ:** ข้อความภาษาไทยทั้งหมดต้องผ่านไฟล์ภาษา `lang/th/*.php` ห้าม Hardcode ภาษาไทยใน Blade
4. **การทดสอบ:** เขียนชุดทดสอบ Feature Test สำหรับหน้าแสดงสต็อก (Happy Path & Multi-Lab Scoping) พร้อมรัน `vendor/bin/pint` ให้ผ่าน 100%
